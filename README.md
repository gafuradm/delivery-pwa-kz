# 🏗️ QazconHub — Цифровая платформа логистического терминала

Современное PWA-приложение для управления логистическим терминалом ТОО «QazconHub»: контейнерные операции, железнодорожные пути (ППЖТ), спецтехника, пропускной режим с OCR, электронная очередь и многое другое.

## ✨ Возможности

### 📊 Обзор терминала
- Живая статистика: завоз/вывоз за сутки, накладные и пропуска, контейнеры, вагоны,
  спецтехника, транспорт, очередь, заявки
- Быстрые действия по ролям

### 📦 Контейнерные операции
- Учёт контейнеров (номер, размер, тип, статус, клиент, груз, вес)
- Размещение на складе: зона / ряд / ярус / уровень
- Поиск и фильтрация

### 📥📤 Завоз и вывоз (документооборот терминала)
- Документы по формам терминала: шапка (организация, движение, способ тр-ки,
  контейнер, категория, статус груза, пломба, номер машины, водитель, вагон,
  склад, контрагент, собственник, получатель, ответственный, комментарий)
- Сквозная нумерация как в бумажных журналах: завоз `06860`, вывоз и накладная `000004855`,
  пропуск `000020129`
- Жизненный цикл документа: черновик → оформлен → завершён / отменён
- Карточка документа редактируемая, как в образце: подписи полей терминала
  (Номер машины, Способ тр-ки, Ответственный, Комментарий, Статус груза) и
  кнопки «ОК» / «Записать» / «Закрыть», дата документа хранится со временем
- Карточка широкая (720px): заголовок и блок кнопок залипают при прокрутке длинной
  формы, на мобильном кнопки выстраиваются в столбик, строки накладной прокручиваются
  внутри окна
- Чекбоксы «Не учитывать вагон» (завоз и вывоз) и «Передан» (вывоз)
- «Ввести пропуск» и «Ввести расходную накладную» прямо по документу — связанный
  документ привязывается к завозу/вывозу
- «Создать вывоз по завозу» и «Создать вывоз по строке накладной» — наследуют
  контейнер, категорию, склад, контрагентов и документ-основание
- Реестр с колонками как в образце (Способ тр-ки, Категория, Статус, Номер машины,
  Вагон, Пропуск, Расходная, Статус документа) и кнопкой «Статус» для быстрой смены
- Фильтры по статусу и поиск по номеру документа, контейнеру, госномеру, водителю

### 🚆 Прибытие ЖД транспортом
- Отдельный реестр прибытия контейнеров по железной дороге: номер документа (`06860`),
  период «прибытие за месяц года» и точное время подачи
- Поля осмотра: код станции, вагон, контейнер, вид (20/40/45/порожний), вес,
  пломба по документу и фактическая пломба — расхождение подсвечивается знаком «≠»
- Сверка пломб выведена отдельной колонкой, счётчиком в сводке и кнопкой
  «Только расхождения пломб»
- Метка ГПС (номер + признак «Метка ГПС»), собственник и грузополучатель из справочника
  контрагентов, ответственное лицо, комментарий, статус ожидается / прибыл / оформлен
- Сводка периода: количество записей, суммарный вес, расхождения пломб, записи с ГПС
  и разбивка по видам контейнера (20 / 40 / 45 / порожний)
- Фильтр по месяцу и году, поиск по номеру документа, контейнеру, вагону, пломбе и ГПС
- PDF-реестр за выбранный месяц одной кнопкой
- Прибытие автоматически создаёт карточки контейнера (вид → размер/тип, статус
  «на терминале») и вагона (операция «прибытие»), если их ещё нет в справочниках

### 🧾 Расходные накладные
- Шапка с доверенностью: «Через кого» (номер доверенности, срок действия, кому
  выдана) и чекбокс «Физ лицо», плюс получатель, собственник, ответственный
- Строки накладной: документ завоза, контейнер, вид груза, категория, единица
  измерения, количество, склад; итог по количеству
- Добавление и удаление строк, статусы черновик / оформлена / закрыта
- Редактируемая карточка (ОК / Записать / Закрыть) и массовые действия:
  «Добавить из отпуска» (пакетно по отмеченным завозам) и «Добавить из завоза»
- «Создать вывоз по текущей строке» — из строки накладной рождается документ вывоза
  с контейнером, категорией, складом и завозом-основанием строки

### 🗂️ Справочники
- Склады, контрагенты (роль в документе, БИН, контакт), ответственные лица
- Значения для форм: статусы, виды транспорта, типы пропусков

### 🚂 Железнодорожные пути (ППЖТ)
- Управление путями и их загрузкой
- Учёт вагонов: прибытие, выгрузка, погрузка, отправка
- Визуализация заполненности путей

### 🏗️ Спецтехника
- Учёт кранов, погрузчиков, тягачей
- Статусы: свободна / работает / на ремонте
- Топливо и моточасы

### 🚛 Транспорт и пропускной режим
- Регистрация въезда/выезда транспорта
- OCR-распознавание госномера (симуляция)
- Управление шлагбаумами
- Выдача пропусков

### 🔢 Электронная очередь
- Запись в очередь по госномеру и цели
- Назначение слотов
- Управление статусами

### 📋 Заявки клиентов
- Создание заявок (контейнер, вагон, хранение)
- Подтверждение и назначение слотов

### 📜 Журнал действий и отчёты
- Полный аудит действий пользователей
- PDF-отчёты по контейнерам, вагонам и реестру прибытия ЖД за месяц

## 🚀 Быстрый старт

### Локально

```bash
# Установка зависимостей
npm install

# Настройка окружения: JWT_SECRET обязателен в продакшене
cp .env.example .env
# и замените значение на случайное, например:
#   openssl rand -hex 32

# Запуск сервера
npm start
```

Сервер запустится на `http://localhost:8080`. Откройте страницу входа и используйте демо-доступы выше.

### Docker

```bash
docker build -t damulogistics .
docker run -p 8080:8080 -e JWT_SECRET="$(openssl rand -hex 32)" damulogistics
```

В образе выставлен `NODE_ENV=production`, поэтому без `JWT_SECRET` контейнер завершится
с ошибкой — это защита от запуска в продакшене на секрете, лежащем в репозитории.

### Fly.io

```bash
fly launch
fly secrets set JWT_SECRET="$(openssl rand -hex 32)"
fly deploy
```

### Тестирование

```bash
npm test        # изолированно: свой сервер на :8099 + временная БД в /tmp, гасится автоматически
```

Smoke + RBAC-проверка API (140 проверок: авторизация, все модули, справочники,
завоз/вывоз с полями «Статус груза» и «Передан», пропуска и расходные накладные по
документу, строки накладной и пакетный подбор `/items/bulk`, вывоз из строки,
реестр прибытия ЖД (период, сводка, расхождения пломб, PDF), PDF-отчёты,
загрузка файлов, разграничение доступа).

Тест **создаёт** записи и не удаляет их за собой, поэтому прямой прогон против рабочей
БД (`server/db/terminal.db`, порт :8080) заблокирован — `test/api-test.js` завершится
с подсказкой. Остальные варианты:

```bash
BASE_URL=https://damulogistics.onrender.com npm run test:direct  # против внешнего стенда
ALLOW_DIRTY_DB=1 npm run test:direct                                 # осознанно в рабочую БД
npm run db:clean-test                                                # dry-run очистки мусора тестов
npm run db:clean-test -- --apply                                     # удалить мусор (с бэкапом БД)
```

[`tools/cleanup-test-data.js`](tools/cleanup-test-data.js:1) находит артефакты автотестов
(контейнеры `TEST*` и `RAIL*`, вагоны `WAG*`/`WAGJ*`, техника/склады/пути «ТЕСТ-*», пропуска
и очередь `P/Q/D/T*`, заявки `REQ*`, документы — включая записи реестра прибытия ЖД —
созданные после 15.09.2026) и откатывает счётчики нумерации `doc_seq` (включая scope
«прибытие жд»), чтобы номера документов шли без пропусков. Отсутствующие в старой БД
таблицы пропускаются, поэтому инструмент безопасен и до первого запуска обновлённого сервера.

## ⚙️ Переменные окружения

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `JWT_SECRET` | — | Секрет подписи JWT. **Обязателен** при `NODE_ENV=production`; без него процесс завершается с ошибкой |
| `PORT` | `8080` | Порт HTTP-сервера |
| `NODE_ENV` | — | `production` включает строгую проверку `JWT_SECRET` |
| `DB_PATH` | `server/db/terminal.db` | Путь к файлу SQLite (удобно для тестов и внешнего диска) |

## 🔒 Безопасность

- Пароли хэшируются через bcrypt
- JWT-токены (7 дней) для авторизации
- Ролевой доступ (RBAC) к каждому модулю
- Rate limiting для API и входа
- Экранирование вывода (XSS-защита)
- Аудит всех действий пользователей

```
tools/
  cleanup-test-data.js — очистка рабочей БД от артефактов тестов (dry-run / --apply)
  build-project-pdf.js — сборка PROJECT.pdf из PROJECT.md
```

## 📘 Описание проекта (PDF)

[`PROJECT.md`](PROJECT.md:1) — источник истины, [`PROJECT.pdf`](PROJECT.pdf:1) собирается из него:

```bash
npm run docs:pdf   # требуется Chrome/Chromium; иначе CHROME_PATH=/путь/к/chrome npm run docs:pdf
```

> При изменении `public/css/*` или `public/js/*` поднимайте версию кэша в
> [`public/sw.js`](public/sw.js:1): статика отдаётся по стратегии cache-first,
> иначе у вернувшихся пользователей останется старая версия интерфейса.
